Payment Demo V5 Architecture

Spring Boot payment demo with React/Vue clients, dynamic payment app configuration, WeChat Pay, Alipay, Redis locks, RabbitMQ delayed close, and MySQL state.

Runtime Flow

  • - Frontends call Spring Boot REST APIs on port 8080.
  • - Orders bind payment_app_id and payment_channel_code.
  • - Provider callbacks update local order and payment state.
  • - RabbitMQ closes stale NOTPAY orders after TTL.

State Surfaces

  • - MySQL owns orders, payment logs, refunds, and app config.
  • - Redis backs Redisson locks and notification idempotency keys.
  • - DB JSON config is cached by PaymentConfigLoader.
  • - application.yml and provider property files remain fallbacks.

Boundary Notes

  • - WeChat V2 and V3 are separate integration paths.
  • - Alipay builds dynamic clients from order-bound app config.
  • - live_spec_template is governance documentation, not runtime.
  • - Public behavior includes callback response formats.
