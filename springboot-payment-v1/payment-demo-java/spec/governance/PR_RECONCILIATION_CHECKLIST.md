## 1. 实现对账

### 1.1 代码与 Spec 一致性

- [ ] 代码行为符合对应 spec 描述的契约
- [ ] 公共 API 路径未改变 (或已标注 `type: compatibility`)
- [ ] 返回结构未改变 (或已标注 `type: compatibility`)
- [ ] 异常类型和消息未改变 (或已标注 `type: compatibility`)

### 1.2 Spec 状态更新

- [ ] 如果实现完成，spec 已从 `planned/` 移到 `implemented/`
- [ ] Spec 文件中的实现锚点已更新
- [ ] Spec 文件中的测试覆盖已更新
- [ ] `spec/README.md` 状态账本已更新

---

## 2. 测试对账

### 2.1 特征测试

- [ ] 全部特征测试通过 (24/24)
- [ ] 新增逻辑有对应特征测试
- [ ] 可疑行为测试已标明 `【现状】`
- [ ] 测试可重复执行，结果稳定

### 2.2 单元测试

- [ ] 新增逻辑有单元测试覆盖

- [ ] 测试隔离了数据库、Redis、RabbitMQ

### 2.3 测试覆盖率

- [ ] 行覆盖率不低于基准 (80%)
- [ ] 分支覆盖率不低于基准 (70%)
- [ ] public API 覆盖率达到 100%

## 对账失败处理

| 失败类型 | 处理方式 |
|---------|---------|
| 实现与 spec 不一致 | 暂停合并，更新 spec 或修正实现 |
| 测试未覆盖 | 补充特征测试，不得跳过 |
| Spec 状态未更新 | 更新 spec 目录状态 |
| 公共 API 意外改变 | 回退变更或升级为 `type: compatibility` |
| 文档未更新 | 补充文档后再合并 |
