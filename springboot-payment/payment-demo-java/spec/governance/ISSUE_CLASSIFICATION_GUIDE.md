# Issue 分类指南

> 本文档帮助团队正确分类 issue，确保处理流程一致。

---

## 分类决策树

```
收到 issue
  ↓
Q1: 是否改变 public API / 返回结构 / 协议格式？
  ├─ 是 → type: compatibility (兼容变更)
  │        ↓
  │       Q: 是否有下游依赖？
  │        ├─ 是 → 必须有兼容方案和迁移指南
  │        └─ 否 → 可直接变更，但需标注版本
  │
  └─ 否 → Q2: 是否改变模块职责、数据流、架构？
           ├─ 是 → type: design-change (设计变更)
           │        ↓
           │       流程: 先更新 spec → 再实现
           │
           └─ 否 → Q3: 是否有多个 issue 指向同一原因？
                    ├─ 是 → type: root-cause-multi (同根因问题)
                    │        ↓
                    │       流程: 合并处理，不逐个打补丁
                    │
                    └─ 否 → type: bug-local (局部 Bug)
                             ↓
                            流程: 直接修复 + 特征测试
```

---

## 分类详细说明

### type: bug-local (局部 Bug)

**定义**: 不影响公共 API，不影响外部调用方，仅内部逻辑错误

**特征**:
- 仅影响特定业务场景
- 不改变函数签名
- 不改变返回结构
- 不改变协议格式

**处理流程**:
1. 编写特征测试锁住当前行为
2. 修复 bug
3. 确认特征测试通过
4. 提交 PR

**示例**:
- 退款金额计算错误 (内部逻辑)
- 订单状态更新时机错误
- 日志输出格式错误

---

### type: design-change (设计变更)

**定义**: 改变架构、模块职责、数据流

**特征**:
- 提取/合并模块
- 改变调用链路
- 引入新的抽象层
- 改变数据访问模式

**处理流程**:
1. 更新 spec (设计文档)
2. 更新架构图
3. 编写特征测试
4. 实施变更
5. 确认特征测试通过
6. 提交 PR

**示例**:
- 提取 V2 通知处理器
- 将同步退款改为异步
- 引入新的缓存策略

---

### type: compatibility (兼容变更)

**定义**: 改变公共 API、返回结构、协议、回调格式

**特征**:
- 改变 URL 路径
- 改变请求/响应格式
- 改变异常类型
- 改变协议版本

**处理流程**:
1. 评估下游依赖影响
2. 设计兼容方案 (如双版本支持)
3. 更新 spec (含兼容说明)
4. 编写迁移指南
5. 编写特征测试
6. 实施变更
7. 提交 PR

**示例**:
- 微信支付 API 从 V2 升级到 V3
- 响应结构从 `code/message` 改为 `code/msg/data`
- 移除废弃的 API 端点

---

### type: root-cause-multi (同根因问题)

**定义**: 多个 issue 源自同一设计缺陷

**特征**:
- 多个 bug 指向同一模块
- 多个性能问题源自同一瓶颈
- 多个安全问题源自同一漏洞

**处理流程**:
1. 识别同根因
2. 关联所有相关 issue
3. 合并到一个 PR 处理
4. 不要逐个打补丁

**示例**:
- 多个并发问题源自同一锁缺失
- 多个数据不一致问题源自同一事务设计
- 多个性能问题源自同一 N+1 查询

## Issue 标签映射

| 分类 | GitHub 标签 | 颜色 |
|------|------------|------|
| bug-local | `type: bug-local` | 🔴 红色 |
| design-change | `type: design-change` | 🟡 黄色 |
| compatibility | `type: compatibility` | 🟠 橙色 |
| root-cause-multi | `type: root-cause-multi` | 🟣 紫色 |

---

## 分类检查清单

在创建 issue 时，回答以下问题：

- [ ] 是否改变 public API 路径？
- [ ] 是否改变返回结构 (code/message/data)？
- [ ] 是否改变请求/响应格式 (JSON/XML/Form)？
- [ ] 是否改变异常类型或消息？
- [ ] 是否改变模块职责或数据流？
- [ ] 是否有其他 issue 指向同一原因？

根据回答，使用上述决策树分类。
