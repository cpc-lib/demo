# 管理员运营边界与主动状态核对设计

## 背景

当前系统把 `USER` 与 `ADMIN` 都视为可购买主体：管理员可以看到课程、读取购物车、结算并发起支付或退款申请。后端已经具备管理员查看全部订单、退款审核和部分渠道查单能力，但两套前端没有把这些运维能力组织成独立入口。

本次调整面向 React 和 Vue 两套前端，要求管理员只参与订单与支付运维，不参与商品购买。

## 目标与边界

- `ADMIN` 对购物车、结算、商品支付、已有订单支付和退款申请统一返回 HTTP 403。
- `USER` 的课程、购物车、结算、支付、退款申请行为保持不变。
- `ADMIN` 可以查看全部订单和订单明细，主动查询支付单状态，审核退款申请，并主动同步退款单状态。
- 复用已有订单、退款列表、审核、退款查询和订单退款核对服务；只为支付宝支付状态同步增加与微信查单对齐的薄包装接口。
- React/Vue 的管理员导航、路由守卫和页面行为保持一致。

不包含管理员用户管理、课程/商品管理、优惠券、库存和新的支付渠道。

## 后端设计

### 购买权限

在 `AuthContext` 增加购买者校验，统一抛出 `ForbiddenException("管理员账号不参与购物")`。以下入口调用该校验：

- `CartController` 的查询、添加、修改、删除、清空；
- `OrderInfoController.checkout`；
- 微信 V3、微信 V2、支付宝的商品支付和已有订单支付入口；
- 三个渠道的退款申请兼容入口。

通知、订单列表、订单明细和管理员运维接口不受该校验影响。课程列表仍可公开读取，管理员前端不提供课程购买入口。

### 管理员查单与退款接口

- 微信支付状态复用 `/api/wx-pay/check-order-status/{orderNo}`，并纳入管理员运维路由；
- 新增 `/api/ali-pay/check-order-status/{orderNo}`，调用现有 `AliPayService.checkOrderStatus`，返回本地订单状态；
- 退款审核复用 `/api/refund-info/list`、`/approve/{refundNo}`、`/reject/{refundNo}`；
- 退款状态复用 `/api/refund-info/query/{refundNo}`；
- 订单下全部退款核对复用 `/api/refund-info/reconcile/{orderNo}`。

所有管理员查单和退款运维接口继续经过 `AuthInterceptor` 与 `AdminInterceptor`，普通用户不能调用管理员列表、审核和核对接口。

## 前端设计

### 共同导航和路由

- ADMIN 隐藏“课程”和“购物车”，登录后根路径进入“全部订单”；
- `/cart`、支付成功页和课程购买动作限制 `USER`；
- ADMIN 导航显示“全部订单”“退款审核”“账单”“支付配置”“对账”；
- ADMIN 不请求购物车数量，避免产生无意义的 403 请求。

### 订单运维页

继续使用现有 `/orders` 路由和订单列表接口。ADMIN 模式只保留：查看订单明细、查询支付状态、查看退款记录、按订单核对退款状态；移除重试支付、取消订单和退款申请。

支付状态按钮按订单支付渠道调用对应查单接口，成功后刷新订单列表。查单接口负责将渠道状态同步到本地订单。

### 退款审核页

新增 ADMIN 保护的 `/refunds` 页面/视图，加载全部退款申请，展示订单号、退款金额、审核状态、退款状态、原因和备注。

- `PENDING` 申请提供“通过”和“拒绝”，可填写审核备注；
- 已通过退款提供“查询状态”，调用统一退款状态同步接口；
- 订单页的“退款状态核对”调用按订单核对接口并刷新退款记录；
- USER 继续在自己的订单页查看退款申请记录，不显示管理员审核操作。

## 数据流与错误处理

管理员查支付状态：前端按钮 → 渠道查单 → 同步本地订单 → 刷新列表。

管理员审核退款：前端按钮及备注 → 现有审核服务 → 渠道退款提交 → 现有异步/主动退款状态同步。

管理员误访问购买接口返回 403 和现有 `R` 错误结构；前端统一显示后端消息。退款未审核时不允许主动查询渠道退款状态，沿用现有服务规则。

## 测试与验收

- 后端特征/单元测试覆盖 ADMIN 对购物车、结算、商品支付、已有订单支付和退款申请的 403；
- 测试支付宝查单薄包装、管理员退款审核和退款状态查询委托；
- 更新权限矩阵测试，确认管理员运维接口仍受保护；
- React、Vue 构建通过；
- 手工验收：ADMIN 无课程/购物车入口，可查看全部订单、查询支付状态、通过/拒绝退款并查询退款状态；USER 购买流程和退款申请保持可用。
