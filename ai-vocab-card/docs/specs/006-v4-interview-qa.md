# V4 面试问答

## 1. 为什么 MySQL、Elasticsearch、语义搜索要拆开？

MySQL 负责事务一致性和主数据；Elasticsearch 负责关键词、中文含义、英文释义等全文检索；语义搜索负责“表达某种含义”的向量或近似匹配查询。这样避免用单一数据库承担所有查询模型。

## 2. 为什么 V4 先实现本地语义搜索降级，而不是强依赖 Milvus？

为了保证项目可运行。企业项目里重型中间件应通过接口隔离。当前 `SemanticSearchService` 使用本地关键词 Jaccard 降级，未来只需要替换为 Milvus Adapter，不影响 Controller 和前端。

## 3. Prompt 为什么要入库？

Prompt 是 AI 应用的业务规则，写死在 Java 里无法灰度、回滚、审计。入库后可以按版本维护，后续支持审批发布、AB Test、模型路由。

## 4. 保存词卡为什么要同步搜索索引和语义索引？

主数据写入 MySQL 后，需要让查询侧尽快可见。V4 当前采用同步尝试 + 失败吞吐的方式保证主流程不受搜索引擎影响；生产版建议改为 Outbox + MQ 异步同步，保证最终一致性。

## 5. SM-2 算法解决什么问题？

它根据用户复习结果动态调整下次复习时间。忘记会缩短间隔，记住会扩大间隔，降低无效重复复习，提高记忆效率。
